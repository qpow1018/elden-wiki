# 흐느낌의 반도 지도 수집 기록

수집 절차는 [지도 데이터 수집 기준](../../../docs/MAP_DATA_IMPORT.md)을 따릅니다. 지역 ID는 `2`이며 현재 개발 모드의 `/maps/2`에만 반영합니다. DB 등록·운영 반영은 하지 않았습니다.

## 원본과 재현

- 원본: [LSDL 본편 지도](https://edring.lsdl.kr/map), 확인일 `2026-11-20`. 원본 적용 게임 버전은 미확인입니다.
- `source.json`: 공개 마커 원본 중 대상 이미지 안의 125개에 대한 ID·이름·좌표·코드·설명을 보존합니다. 전체 2,096개 좌표 인덱스로 이미지 범위 선택을 다시 계산할 수 있습니다. 사용자 계정 정보는 저장하지 않습니다.
- 분류는 공개 `map.js`의 마커 코드 매핑을 사용합니다. 원문 설명 키워드로 추가되는 검색 필터를 아이템 자체의 분류로 확장하지 않습니다. 예를 들어 상점 설명에 무기가 있어도 NPC를 무기 마커로 바꾸지 않습니다.
- `review.json`: 125개 설명 전체의 검토 결과, 획득 목록과 보류 이유, 기존 CSV 35개 및 기존 획득 목록의 대응을 기록합니다. LSDL 제목이 없는 순례교회·제4 마리카 교회·은둔 상인의 오두막은 CSV의 같은 장소와 대조해 기존 한국어 표시명을 유지합니다.
- `../generate.mjs`: 표준 Node.js 모듈과 프로젝트에 설치된 Prettier로 좌표·분류·획득 목록을 생성합니다. 네트워크 요청은 하지 않습니다. 지도 이미지 해시와 원본·검토 ID 집합을 확인하며 반도 데이터 블록만 갱신합니다.

저장소 루트에서 실행합니다. 원본·검토 파일 또는 지도 이미지가 바뀌면 검증 결과를 다시 확인해야 합니다.

```bash
node reference-data/maps/generate.mjs weeping-peninsula
node reference-data/maps/generate.mjs weeping-peninsula --check
```

검증 명령은 스냅샷과 현재 코드의 일치를 확인합니다. LSDL 사이트가 이후 갱신됐는지 또는 사람이 정리한 획득 목록의 의미가 올바른지까지 자동 검증하지는 않습니다.

## 이미지 정합

- 이미지: `src/assets/images/maps/2_weeping_peninsula.webp`, `4200×4200`. SHA-256은 `source.json`에 보존합니다.
- 원본 타일: `https://edring.lsdl.kr/assets/maptiles/5/tile_{x}_{y}.jpg`, x `10..15`, y `24..30`, 타일 크기 `256×256`. 모자이크 원점은 `(2560, 6144)`입니다.
- `u = sourceX × 32 - 2560`, `v = -sourceY × 32 - 6144`에 `source.json`의 2×3 변환 행렬을 적용합니다. 결과 픽셀을 각각 4200으로 나누고 마지막에 소수점 여섯 자리로 반올림합니다. 경계 좌표를 강제로 잘라 넣지 않습니다.
- 정합 방법: 원본 모자이크와 대상 이미지의 40% 축소본에서 SIFT 특징점 최대 16,000개를 추출하고, BFMatcher 2근접 비율 `0.65`로 매칭했습니다. 대상 좌표를 원래 크기로 복원한 뒤 `estimateAffine2D`의 RANSAC 기준 4px로 변환을 추정했습니다. 일치 후보 4,103개 중 4,086개를 채택했습니다.
- 채택점의 잔차 중앙값 약 `0.48px`, 95백분위 약 `1.60px`입니다. 별도 확인에서는 난수 시드 20으로 매칭 후보의 20%(814개)를 분리하고 나머지로 변환을 추정했습니다. 분리한 814개 중 812개가 5px 이내였고, 전체 중앙값 `0.50px`, 95백분위 `1.60px`입니다. 나머지 두 개는 불일치점입니다.
- 분리 표본은 이미지의 3×3 모든 구역에 분포하며 구역별 95백분위가 약 `1.35~2.10px`입니다. 서쪽 교회·동쪽 탑·남쪽 몬 성의 원본/대상 지형 확대 비교도 확인했습니다. 이는 지형 정합 검증이며 LSDL 개별 마커의 게임 내 정확성 검증은 아닙니다.

## 반영 범위와 기존 데이터 대응

- 최종 이미지 범위 후보 125개를 모두 반영했습니다. 제외 0개, ID 중복 0개이며 원본 좌표 인덱스로 계산한 후보 집합과 일치합니다. 북쪽에 보이는 림그레이브·용찬 교회 주변도 이미지 범위에 포함합니다. `LSDL-1668` 안내 마커 역시 림그레이브와 같은 방식으로 유지합니다.
- 복수 분류는 하나의 마커에 유지합니다. 원본 코드로 분류되지 않은 40개도 제외하지 않았습니다. 이름 없는 영기류 마커 `LSDL-1295`의 원본 제목은 비어 있으며 임의 명칭을 채우지 않았습니다.
- 설명 125개를 검토해 61개 마커에 획득 목록 100건을 연결했습니다. 개별 아이템의 명시된 수량도 획득 목록에 포함하므로, 100건이 서로 다른 아이템 종류 수를 의미하지는 않습니다.
- 기존 CSV 축복 18개·장소 15개·NPC 2개는 모두 LSDL에 대응돼 중복 CSV 마커를 교체했습니다. `review.json`의 `legacy`에서 원본 ID와 새 ID를 찾을 수 있습니다. 동굴의 축복과 장소처럼 둘이 하나의 원본 마커로 합쳐진 경우도 있습니다. CSV 장소 좌표와 LSDL의 장소 대표점이 다른 경우 LSDL 좌표를 채택했습니다.
- 기존 몬 성 목록의 석검 열쇠는 성 `LSDL-314`, 강선 토치는 `2260`, 채찍은 `2262`, 쌍날검의 탈리스만은 `1831`, 클레이모어는 `2259`로 대응됩니다. 메모리 스톤은 탑 `LSDL-321` 목록에 유지합니다.
- 몬 성의 목록과 개별 아이템 마커는 원본의 서로 다른 표현으로 함께 유지합니다. 원본 `LSDL-314`가 위치 미표시 목록으로 적은 채찍·단석 일부 등과 별도 마커는 수량을 합산하지 않습니다. 이 자료는 지역 총 획득 수량 계산용 목록이 아닙니다.
- 림그레이브 데이터·마커 UI·DB 구조는 변경하지 않았습니다.

## 보류와 해석

- 상인 `1280`, `1297`은 위치를 표시하되 판매 목록을 일반 획득 목록에 넣지 않았습니다. 용찬 교회 `1667`의 용의 심장 교환도 별도로 보류합니다.
- 에드거 `1064`, 블라이드 `1251`, 셀렌 `1836`의 조건부 보상은 대화·처치·진행 조건을 잃지 않도록 원문과 검토 이유에 보존했습니다. 현재 UI에는 퀘스트 조건 표시 구조가 없습니다.
- 반복·무작위 드롭을 설명하는 파밍 지점은 마커를 표시하고 원문에 드롭 설명을 남겼습니다. 파밍 수량을 일회 획득 수량으로 저장하지 않았습니다.
- 던전 제작서의 석검 열쇠 요구량은 획득품이 아닙니다. 원문과 검토 이유에 보존하고, 제작서가 여는 제작법을 별도 획득 아이템으로 넣지 않았습니다.
- 밤 기병 `1281`과 죽음의 새 `1283`는 밤에 출현합니다. 목록은 해당 보스의 처치 보상이며 출현 시간 안내는 원문에 보존합니다. 지역 목록을 자동 획득이나 무조건 지급으로 해석하지 않습니다.
- 첨부 이미지와 수량·보상이 다를 때는 LSDL을 기본으로 채택했습니다. 인게임 전체 배치·모든 수량을 별도로 확인한 결과는 아닙니다.

## 화면·소스 검증

- PC 기본 뷰포트와 모바일 `390×844`에서 마커 표시, 탑 메모리 스톤·꼬챙이 묘지 목록·사자 혼종 보상·묘지 룬 목록과 수량을 확인했습니다.
- 모바일에서 최대 8배 확대, 드래그 이동, 오리티스의 탑 지형과 마커 위치, 선택 해제와 전체 보기 복귀를 확인했습니다. 동명 석검 열쇠 두 마커의 독립 선택도 확인했습니다.
- 전체 보기에서는 가까운 마커의 클릭 영역이 겹칩니다. 모닝스타를 클릭했을 때 단석 마커가 선택되는 기존 UI 한계가 있어 해당 항목은 키보드로 독립 선택했습니다. 밀집 마커의 선택 UI는 이번 데이터 변경 범위에 포함하지 않았습니다.
- 생성 결과 대조, 림그레이브 데이터와 공통 타입·함수의 변경 없음, lint·typecheck·변경 파일 포맷과 diff 검사를 확인했습니다. 실제 Android Chrome·iOS Safari 기기 검증은 하지 않았습니다.
