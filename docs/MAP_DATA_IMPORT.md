# 지역별 지도 데이터 수집 기준

지역 지도에 마커와 획득 정보를 추가할 때 사용하는 절차입니다. LSDL을 기본 출처로 삼고, 보유 지도 이미지에 좌표를 맞춥니다. 게임 내 모든 배치의 완전성을 보장하는 기준은 아니며, 수집한 원본 범위와 검증하지 못한 부분을 구분합니다.

## 출처와 현재 저장 위치

- 기본 출처는 [LSDL 공개 지도](https://edring.lsdl.kr/map)입니다. 본편과 DLC 지도를 구분하고, 원본이 밝히지 않은 게임 버전은 미확인으로 기록합니다.
- 지역 ID와 배경 이미지는 [mapRegions.ts](../src/app/maps/_define/mapRegions.ts), 개발용 마커는 [mapMarkerSamples.ts](../src/app/maps/[regionId]/mapMarkerSamples.ts)에서 관리합니다. 현재 [지역 페이지](../src/app/maps/[regionId]/page.tsx)는 개발 모드에서만 마커를 전달합니다. 개발용 파일 반영과 운영 데이터 등록은 별개입니다.
- 사용자가 제공한 지도 이미지는 누락·지형 대조에 사용합니다. 오래된 보상 정보일 수 있으므로 무조건 정답으로 취급하지 않습니다.
- 게임 원본으로 보완할 때는 [게임 CSV와 한국어 텍스트 출처](DATA_SOURCES.md)를 확인합니다. CSV 행의 영문 이름보다 실제 참조 ID와 한국어 FMG를 대조합니다. CSV에 아이템이 있어도 개별 배치 좌표까지 있다는 뜻은 아닙니다.

## 지역마다 수행할 순서

### 1. 대상과 원본을 고정

1. 지역 ID, 이미지 경로·해상도, 본편/DLC 범위를 확인합니다.
2. 수집 시점의 원본 URL·확인일과 마커 원본을 보관합니다. 공개 HTML의 `gmarkers`와 필터 매핑 스크립트는 구조가 바뀔 수 있으므로 매번 실제 내용을 확인합니다.
3. 원본의 번호·이름·좌표·마커 코드·설명(`no`, `label`, `x`, `y`, `marker`, `desc`)을 함께 확보합니다. 제목·좌표만 추출하지 않습니다.
4. 원본 스냅샷과 재실행 가능한 추출·변환 방법의 보관 경로를 남깁니다. `/tmp` 경로만 남기면 다음 작업에서 재현할 수 없으므로 영구적인 근거로 사용하지 않습니다. 원본 전체를 앱 데이터에 복제할 필요는 없습니다.

지역 선택은 원본의 지역명이나 아이템 분류가 아니라 **대상 이미지에 들어오는 좌표 범위**로 판단합니다. 경계에 보이는 인접 지역도 포함하고, 제외하는 경우 ID와 이유를 남깁니다. 이미지 밖의 장소를 설명에서 언급했다는 이유로 해당 이미지에 새 마커를 만들지 않습니다.

### 2. 지도 이미지와 좌표를 정합

- LSDL 타일과 보유 이미지의 같은 지형을 비교합니다. 마커 아이콘 중심을 지형 기준점으로 삼지 않습니다.
- 원본 좌표계, 타일 줌·크기·원점, 대상 이미지 해상도와 변환 계수를 기록합니다. 다른 지역의 계수를 그대로 복사하지 않습니다.
- 별도 지형이 삽입된 합성 이미지는 영역별 변환과 표시 범위를 기록합니다. 본 지도에서는 삽입 영역에 가려진 좌표를 제외하고, 삽입 지형은 자체 변환으로 배치합니다. 전체 이미지에 변환 하나를 적용하지 않습니다.
- 가능하면 이미지 특징점으로 변환을 추정하고 이상치를 제외합니다. 일치점이 중앙에만 몰리지 않도록 모서리·경계와 여러 구역에서 확인합니다. 자동 정합이 어려우면 이미지 전역에 분산된 지형 기준점을 사용하고 근사 변환임을 명시합니다.
- 원본 좌표를 이미지 픽셀 좌표로 변환한 뒤 `x = pixelX / imageWidth`, `y = pixelY / imageHeight`로 정규화합니다. 중간 계산은 반올림하지 않고 최종 저장값에서 반올림합니다. 현재 림그레이브는 소수점 여섯 자리입니다.
- 최종 변환으로 이미지 내부 후보를 다시 추립니다. 수집 초기의 근사 범위에서 빠진 경계 마커가 없는지 확인하고, 이미지 밖 좌표를 임의로 `0~1` 안으로 잘라 넣지 않습니다.
- 적합에 사용한 점 외의 지형으로도 결과를 확인하고, 잔차와 최대 확대 화면에서 보이는 차이를 기록합니다. 이미지 정합 오차와 LSDL 개별 마커 자체의 위치 오차를 구분합니다.

LSDL이 `L.CRS.Simple`을 사용하는 현재 구조에서 타일 줌 `z`의 픽셀은 `px = sourceX * 2^z`, `py = -sourceY * 2^z`입니다. 이 공식은 해당 좌표계가 유지되는지 확인한 뒤 사용합니다. 타일 모자이크를 잘랐다면 원점을 뺀 좌표를 변환식에 넣습니다.

림그레이브 보정의 예시는 코드 상단 주석에 있습니다. 줌 5 타일 원점 `(2560, 5120)`과 대상 이미지 `5100×4860`에 맞춘 식으로, 흐느낌의 반도용 식이 아닙니다.

### 3. 모든 종류의 마커를 추출

- 아이템뿐 아니라 축복·장소·던전·NPC·보스·암령·채집·파밍 등 이미지 범위 안의 원본 마커 전체를 대상으로 합니다.
- ID는 `LSDL-<원본 마커 번호>`로 유지합니다. 이름이 같아도 번호가 다르면 별도 위치이며, 이름으로 중복 제거하지 않습니다.
- 하나의 원본 마커가 여러 필터에 해당하면 마커 하나에 여러 `categories`를 저장합니다. 원본 필터 매핑이 확인되지 않은 경우 `[]`로 남기며, 분류가 없다는 이유로 제외하지 않습니다.
- 분류는 원본 필터에 맞춥니다. UI 아이콘을 다르게 보이게 하려고 원본 분류를 임의로 바꾸지 않습니다.
- 이름 없는 마커도 원본 ID를 보존하고 표시용 이름만 정합니다. 자료 안내 등 위치 정보와 성격이 다른 마커가 있으면 포함 여부를 검토하고 제외 사유를 남깁니다.

### 4. 설명 속 획득 정보를 별도로 정리

- 모든 후보의 `desc`를 확인합니다. 제목에 없는 던전 내부 아이템·보스 보상·묘지의 룬도 해당 마커의 `loot`로 연결합니다.
- 수량은 원문에 명시된 경우에만 저장합니다. 미기재 수량을 확인된 `1`로 바꾸지 않습니다.
- 여러 획득물이 같은 던전이나 장소 설명에 묶여 있으면 목록으로 유지합니다. 개별 상자·시체 좌표를 추정해서 만들지 않습니다.
- 상점 판매, 제작법 해금, 퀘스트의 다른 장소 언급은 현 위치의 획득 목록과 구분합니다. 현재 `loot` 구조로 표현하기 어려운 조건부 보상은 조건을 지우고 확정 보상처럼 넣지 말고 보류 이유를 기록합니다.
- 설명 속 아이템에 별도 원본 마커가 있는지 확인합니다. 이름이 같다는 이유로 기존 마커를 지우거나, 설명에 나왔다는 이유만으로 새 마커를 추가하지 않습니다. 개별 위치와 장소 전체 목록이 함께 남는 경우 그 관계를 점검합니다.
- 획득 항목 ID는 현재 파일의 `LSDL-<마커 번호>-<항목 번호>` 형식을 따릅니다. 갱신 시 기존 항목 ID를 가능한 한 유지합니다.

마커 수와 획득 항목 수는 별개입니다. 이미지에 점 일곱 개가 있어도 LSDL에서는 묘지 마커 하나의 룬 일곱 개로 묶일 수 있습니다. 점 개수만으로 누락이나 일치를 확정하지 않습니다.

### 5. 기존 데이터와 대조한 뒤 반영

- 기존 CSV 마커가 있는 지역에서는 같은 장소·축복·NPC가 중복 표시되는지 확인합니다. ID 체계가 다르므로 이름·설명·위치를 함께 비교합니다.
- LSDL로 대체하기 전에 기존 마커와 획득 목록의 대응을 정리합니다. LSDL에서 찾지 못한 CSV 정보는 자동 삭제하거나 근거 없이 LSDL 좌표에 합치지 않고, 유지·통합·보류 이유를 남깁니다.
- 자료가 충돌하면 원본 ID와 실제 지급 데이터를 확인합니다. 판단할 수 없으면 미확인으로 남깁니다.
- 현재 개발용 구조에서 필요한 데이터만 변경합니다. 수집을 이유로 DB·운영 데이터·마커 UI까지 함께 변경하지 않습니다.

## 검증과 완료 판단

다음 항목을 지역별로 확인합니다. 소스 검사·화면 검사 등 공통 검증 명령은 [작업 지침](../AGENTS.md#자체-검토와-검증)을 따릅니다.

- **원본 대비 전수 대조:** 최종 이미지 범위 후보 ID 집합과 반영 ID 집합을 비교합니다. 누락·추가·중복을 확인하고 의도적인 제외는 별도로 셉니다. 같은 개수라는 것만으로 통과하지 않습니다.
- **좌표:** 전 마커의 원본→변환→저장값을 비교하고 반올림 오차를 확인합니다. 전체 보기와 최대 확대에서 여러 구역의 지형 정합·경계 위치를 확인합니다.
- **분류:** 복수 분류와 미분류 마커가 보존됐는지 확인합니다. 분류별 개수의 합은 마커 수와 다를 수 있습니다.
- **획득 정보:** 모든 설명의 검토 여부를 확인하고, 목록이 있는 마커 수·획득 항목 수·수량·보류 사항을 별도로 집계합니다.
- **화면:** PC·모바일에서 단일 아이템·던전·보스·묶음 획득 목록을 선택하고, 동명 마커·겹침·선택 해제·이동·확대를 확인합니다.
- **변경 범위:** 다른 지역 데이터가 의도치 않게 바뀌지 않았는지 확인합니다. 개발용 반영과 운영 반영 상태를 구분합니다.

완료 보고는 “해당 날짜에 수집한 원본의 이미지 범위 내 마커와 설명을 검토했다”처럼 확인 범위를 밝힙니다. 미확인·제외·보류가 남아 있으면 함께 표시하고, 이를 게임 내 모든 아이템의 개별 위치 검증으로 표현하지 않습니다.

## 지역별 기록 양식

지역 작업의 검토 기록에 다음 항목을 남깁니다. 이 문서에는 실행 로그나 지역별 전체 데이터 목록을 누적하지 않습니다.

```text
지역 ID / 이름:
이미지 경로 / 해상도 / 변경 식별 정보:
본편 또는 DLC / 원본 URL / 확인일 / 원본 적용 버전(미확인 허용):
원본 스냅샷 / 추출·변환 방법 보관 경로:

정합 검증 범위 / 일치점 수 / 잔차 / 별도 지형 확인:
최종 이미지 범위 후보 수 / 반영 수 / 제외 ID와 이유:
ID 집합 비교 결과 / 복수 분류·미분류 확인:

PC·모바일 및 최대 확대 확인 / 소스 검사 결과:
개발용·로컬 DB・운영 반영 구분:
```

## 기존 작업에서 확인한 주의점

- 림그레이브는 아이템·지도 조각 73개에서 시작해 다른 종류 159개를 추가했습니다. 이후에도 설명 속 획득 정보가 빠져 있어 55개 마커에 146건을 연결했습니다. **위치 수집과 설명 검토를 별도 단계로 수행해야 하는 이유**입니다.
- 림그레이브의 최초 근사 좌표는 전체 보기에서는 비슷했지만 최대 확대에서 차이가 났습니다. 이후 지형 특징점으로 전체 변환을 보정했습니다. 개별 마커를 수동 이동하기 전에 공통 변환을 확인합니다.
- 흐느낌의 반도는 LSDL 수집 전 CSV 기반 데이터가 들어간 상태입니다. CSV의 지역명만으로 추릴 때 오리티스의 마술사탑이 누락됐고, 모닝스타는 보상 행이 있어도 개별 좌표가 없어 표시하지 못했습니다. **지역명·아이템 존재 여부와 배치 위치 확보를 구분**합니다.
- 흐린 강의 지하 묘지 보상은 첨부 이미지·CSV 영문 행 이름과 실제 지급 ID가 달랐습니다. 게임 원본의 지급 ID와 한국어 텍스트를 대조한 결과 LSDL의 땅 잃은 기사 잉바르를 채택했습니다. 오래된 이미지나 행 이름만으로 덮어쓰지 않습니다.
