# 데이터베이스 설계

## 목적과 기준 자료

이 문서는 대화 세션이 바뀌어도 데이터 구조와 설계 결정을 확인하고, 조회·화면·데이터 등록 등 후속 기능을 일관되게 개발하기 위한 참조 문서입니다. 이전 대화 내용을 알고 있다고 가정하지 않습니다.

| 확인 대상                       | 기준 자료                                        |
| ------------------------------- | ------------------------------------------------ |
| 테이블·컬럼·DB 제약·권한        | `supabase/migrations/*.sql`을 적용 순서대로 확인 |
| 로컬 초기 데이터 등록 설정      | `supabase/seed.sql`                              |
| 로컬 서비스·시드 실행 설정      | `supabase/config.toml`                           |
| 설계 의도·값의 의미·미구현 범위 | 이 문서                                          |
| 특정 환경의 적용 여부·현재 행   | 해당 DB의 마이그레이션 이력과 실제 조회          |

문서와 SQL이 다르면 SQL로 구현 상태를 확인하고 차이를 명시합니다. 이 문서만으로 운영 반영 여부나 현재 데이터 전체를 판단하지 않습니다. 스키마·시드·설계 결정이 바뀌면 관련 설명과 예시도 함께 갱신합니다.

개발 환경은 Docker 로컬 Supabase, 운영 환경은 Supabase 클라우드로 분리합니다. 현재 마이그레이션과 시드 적용은 로컬에서 검증했습니다.

## 명칭 기준

- 도감 UI·경로는 `catalog`, 개별 게임 아이템과 API 도메인은 `gameItem`을 사용합니다.
- DB에서는 snake_case로 `game_items`, `game_item_categories`, `game_item_type`, `game_item_id`를 사용합니다.
- `20261102011418_rename_game_item_domain.sql`에서 기존 이름을 변경합니다. 이전 마이그레이션은 당시 이름을 유지합니다.
- API 응답은 `gameItems`, `gameItemCategories`, `gameItemId`로 명시적으로 변환합니다.
- 이름 변경 마이그레이션을 로컬 DB에 적용하고 게임 아이템 24개 유지, 시드 재실행, 공개 조회와 쓰기 제한을 확인했습니다. 운영 DB 적용은 수행하지 않았습니다.

## 개발 전에 확인할 확정 규칙

- 공통 아이템 식별자는 `game_items.id`입니다. 이름에는 고유 제약이 없으므로 기능에서 이름을 식별자로 사용하지 않습니다.
- `type`은 무기·주문 등의 종류, `category_id`는 단검·마술 등의 세부 분류입니다. 두 종류가 일치해야 한다는 규칙은 복합 외래키로 보장합니다.
- 이미지·콘텐츠 소속·게임 내 설명은 공통 정보입니다. 일반 설명은 제외했습니다. 게임 내 원문과 사용자 해설을 같은 컬럼에 섞지 않습니다.
- `content_code`는 콘텐츠 소속이며 판매 에디션·현재 소유 여부·획득 장소를 뜻하지 않습니다.
- 무기는 기본 전투 기술을 참조합니다. 전회 아이템과 전투 기술을 동일한 데이터로 취급하지 않습니다. 사용자의 전회 장착 상태는 저장하지 않습니다.
- 공격력·가드 성능은 표준 변질(변질 불가 무기는 기본 상태)의 최대 강화 기준, 변질별 보정은 각 변질의 최대 강화 기준, 부가 효과는 미강화 기본 수치입니다. 공격력은 캐릭터 능력치로 더해지는 공격력과 일시적 버프를 제외한 무기 자체 수치이고, 부가 효과도 캐릭터 능력치 보정·일시적 버프를 제외합니다. 이들을 동일한 조건의 수치로 계산하지 않습니다.
- 강화 단계 컬럼은 의도적으로 제외했습니다. `weapon_scalings`의 변질 선택에 맞춰 `weapon_details`의 공격력이 바뀐다고 가정하지 않습니다.
- 분류와 아이템의 `sort_order`는 등록 시 명시하는 양의 정수입니다. 분류는 같은 종류 안에서, 아이템은 같은 분류 안에서 작은 값부터 표시합니다. ID와 입력 순서는 표시 순서가 아닙니다.
- 수치의 `0`과 `NULL`, 보정 등급의 `-`와 `NULL`은 구분합니다. 사용자 입력 기준에 따라 자료 표에 수면·발광 항목이 없으면 해당 축적 수치는 없음(`0`)으로 저장합니다. 그 외 미확인 값을 임의로 0이나 보정 없음으로 변환하지 않습니다.
- 인게임 확인이 필요한 미확인 정보는 [데이터 확인 목록](DATA_VERIFICATION.md)에 기록하고, 확인 후 DB·시드와 함께 갱신합니다.
- 공격 속성 배열은 출력 시 정렬합니다. 구체적인 표시 순서는 미확정이며 배열 저장 순서를 표시 규칙으로 삼지 않습니다.
- 모든 현재 테이블은 공개 조회용입니다. 로그인만으로 수정 권한이 생기지 않습니다. 쓰기·댓글·비공개 콘텐츠 기능은 별도 설계가 필요합니다.

## 테이블 관계

```mermaid
erDiagram
  game_item_categories ||--o{ game_items : "분류"
  game_items ||--o| ash_of_war_details : "전회 상세"
  weapon_skills o|--o{ ash_of_war_details : "부여 기술"
  game_items ||--o| spell_details : "주문 상세"
  game_items ||--o| talisman_details : "탈리스만 상세"
  game_items ||--o| armor_details : "방어구 상세"
  game_items ||--o| weapon_details : "무기 상세"
  weapon_skills o|--o{ weapon_details : "기본 전투 기술"
  weapon_details ||--o{ weapon_scalings : "변질별 보정"
```

- 모든 획득 대상은 `game_items`에 저장하고, 종류별 정보는 상세 테이블로 분리합니다.
- 현재 상세 테이블은 무기·방어구·탈리스만·주문·전회를 구현했습니다. `game_items` 행만 있고 무기 상세가 없는 상태도 허용합니다.
- 무기는 기본 전투 기술 하나를 선택적으로 참조합니다. 여러 무기가 같은 기술을 참조할 수 있습니다.
- 전회는 획득 아이템이고 전투 기술은 발동하는 기술입니다. 전회는 `ash_of_war_details.skill_id`로 부여하는 기술을 참조합니다.
- 외래키는 모두 `ON UPDATE RESTRICT`, `ON DELETE RESTRICT`입니다. 참조 중인 키의 변경·삭제를 막으며 자동 연쇄 삭제는 하지 않습니다.

## 공통 종류: `game_item_type`

`game_items`, `game_item_categories`, `weapon_details`, `armor_details`에서 사용하는 PostgreSQL enum입니다.
이 문서의 코드 대응은 현재 스키마와 합의한 한국어 명칭을 기준으로 합니다. 모든 용어를 공식 현지화 자료와 별도 대조했다는 의미는 아닙니다.

| 값             | 의미        |
| -------------- | ----------- |
| `weapon`       | 무기        |
| `catalyst`     | 촉매        |
| `other_weapon` | 기타 무기   |
| `armor`        | 방어구      |
| `talisman`     | 탈리스만    |
| `ash_of_war`   | 전회        |
| `spell`        | 주문        |
| `other`        | 아이템      |
| `crystal_tear` | 결정 물방울 |
| `spirit_ash`   | 뼛가루      |

`20261102015026_replace_gesture_type_with_other.sql`에서 미사용 `gesture` 값을 `other`로 교체합니다. 표시명은 아이템이며 DB 키 `other`는 유지합니다. 도구·소모품·재료 등 세부 분류는 실제 등록 시 정의합니다. 현재 `other`의 아이템과 세부 분류는 없습니다.

- `20261103064447_add_weapon_catalog_types.sql`에서 타입을 추가하고 다음 마이그레이션에서 기존 분류·아이템·무기 상세를 함께 이동합니다. ID와 표시 순서는 보존하며, 복합 외래키와 공개 조회 전용 권한을 유지합니다.
- 촉매·기타 무기는 우선 기존 `weapon_details`·`weapon_scalings`를 사용합니다. 촉매·기타 무기의 상세 등록 시 `type`을 부모와 동일하게 명시해야 합니다. 사거리·시전 보정 같은 전용 필드와 화면은 아직 구현하지 않았습니다.

## `game_item_categories`: 세부 분류

직검·단검·투구처럼 각 종류 안의 세부 분류를 관리합니다. 분류는 실제 아이템을 입력할 때 추가할 수 있습니다.

| 컬럼         | 자료형           | NULL 허용 | 의미                                                 |
| ------------ | ---------------- | --------- | ---------------------------------------------------- |
| `id`         | `bigint`         | 아니요    | 자동 생성 기본키                                     |
| `name`       | `text`           | 아니요    | 분류명. 빈 문자열·공백만 있는 값 금지                |
| `type`       | `game_item_type` | 아니요    | 분류가 속한 종류                                     |
| `sort_order` | `integer`        | 아니요    | 같은 종류 안의 표시 순서. 1 이상의 정수, 기본값 없음 |

- `(type, name)`은 고유합니다. 같은 종류에 같은 분류명을 중복 등록할 수 없습니다.
- `(id, type)` 고유 제약은 아이템에서 ID와 종류를 함께 참조하기 위해 사용합니다.

## `game_items`: 획득 대상의 공통 정보

| 컬럼                 | 자료형           | NULL 허용 | 의미                                                        |
| -------------------- | ---------------- | --------- | ----------------------------------------------------------- |
| `id`                 | `bigint`         | 아니요    | 자동 생성 기본키                                            |
| `name`               | `text`           | 아니요    | 아이템 이름. 빈 문자열·공백만 있는 값 금지                  |
| `type`               | `game_item_type` | 아니요    | 획득 대상의 종류                                            |
| `category_id`        | `bigint`         | 아니요    | 세부 분류 ID                                                |
| `sort_order`         | `integer`        | 아니요    | 같은 분류 안의 표시 순서. 1 이상의 정수, 기본값 없음        |
| `image_url`          | `text`           | 예        | 이미지 주소. URL 형식·접근 가능 여부는 DB에서 검증하지 않음 |
| `content_code`       | `text`           | 아니요    | 콘텐츠 소속. 아래 세 값만 허용하며 기본값 없음              |
| `game_description`   | `text`           | 예        | 게임 내 설명 원문                                           |
| `effect_description` | `text`           | 예        | 아이템 부가 효과의 표시용 설명                              |

| `content_code`          | 의미               |
| ----------------------- | ------------------ |
| `base_game`             | 본편               |
| `shadow_of_the_erdtree` | 황금 나무의 그림자 |
| `tarnished_pack`        | 빛바랜자 에디션    |

`tarnished_pack`은 사용자 결정에 따라 서비스에서 '빛바랜자 에디션'으로 표시합니다. 이는 서비스 표시명이며, 저장 값은 추가 콘텐츠 팩(Tarnished Pack)을 뜻합니다.
콘텐츠 소속과 실제 획득 장소·진행 조건은 구분합니다. 여러 콘텐츠를 묶은 판매 상품인 Tarnished Edition은 별도 값으로 두지 않습니다.
일반 해설·사용자 설명은 현재 저장하지 않습니다.
부가 효과는 `effect_description`에 설명으로만 저장합니다. NULL은 효과 없음 또는 미입력이며 구분하지 않습니다. 효과별 필터·계산용 구조는 두지 않습니다. 무기의 출혈·동상 등 축적 수치는 기존 전용 컬럼을 유지합니다.

- `(category_id, type)`이 `game_item_categories(id, type)`을 참조합니다. 무기에 방어구 분류를 연결할 수 없습니다.
- `(id, type)`은 무기 상세의 복합 외래키를 위한 고유 제약입니다.
- 아이템 이름에는 고유 제약이 없습니다. 이름이 아닌 ID가 식별 기준입니다.
- `(category_id, type)` 인덱스가 있습니다.

## 도감 표시 순서

- 분류 목록은 `type → sort_order → id` 순으로 조회하고, 화면에서 현재 종류만 표시합니다.
- 아이템은 `분류 sort_order → category_id → 아이템 sort_order → 아이템 id` 순으로 DB에서 정렬한 뒤 페이지네이션합니다. 분류 필터를 적용해도 같은 기준을 사용합니다.
- 순서 중복은 허용합니다. 분류 순서가 같으면 분류 ID로 그룹을 유지하고, 같은 분류 안의 아이템 순서가 같으면 아이템 ID로 순서를 확정합니다.
- 등록할 때 `sort_order`를 반드시 지정합니다. 간격을 둔 값(예: 10, 20, 30)도 가능하며, 순서 변경은 해당 값의 수정으로 처리합니다. 관리 화면과 쓰기 API는 아직 구현하지 않았습니다.
- `20261103061915_add_catalog_sort_order.sql`은 기존 데이터가 있는 환경에서 분류는 기존 이름순, 아이템은 분류 내 ID순으로 초기 값을 채웁니다. 새 순서 기준 적용 후에는 전체 아이템이 분류별로 모입니다.
- 분류 인덱스 `(type, sort_order, id)`, 아이템 인덱스 `(category_id, sort_order, id)`가 있습니다. 로컬에만 적용했으며 운영 반영은 수행하지 않았습니다.

| 컬럼           | 자료형   | NULL 허용 | 의미                                                                |
| -------------- | -------- | --------- | ------------------------------------------------------------------- |
| `id`           | `bigint` | 아니요    | 자동 생성 기본키                                                    |

이름에는 고유 제약이 없습니다. FP 문자열을 이용한 수치 계산·정렬 기능은 구현하지 않았습니다.

## `weapon_details`: 무기 상세

무기 하나당 최대 한 행을 저장합니다. 아래 표에서 키·종류 외 컬럼은 모두 NULL을 허용합니다.
수치의 `0`은 해당 수치·효과·요구 조건 없음, `NULL`은 미확인을 뜻합니다.

### 기본 특성

| 컬럼                    | 자료형           | 의미·제약                                                                                              |
| ----------------------- | ---------------- | ------------------------------------------------------------------------------------------------------ |
| `game_item_id`          | `bigint`         | 기본키. 아래 `type`과 함께 `game_items(id, type)` 참조                                                 |
| `type`                  | `game_item_type` | 기본값 `weapon`, NULL 불가. `weapon`·`catalyst`·`other_weapon`만 허용. 부모 아이템과 타입 일치 필수    |
| `weight`                | `numeric`        | 중량, 0 이상                                                                                           |
| `can_change_affinity`   | `boolean`        | `true`: 변질 가능, `false`: 변질 불가, NULL: 미확인. 기본값 없음                                       |
| `physical_attack_types` | `text[]`         | 물리 공격 방식 목록. 아래 값만 허용하며 배열 내부 NULL 금지                                            |
| `upgrade_material`      | `text`           | `smithing_stone`(단석), `somber_smithing_stone`(색 잃은 단석), `none`(강화 불가)만 허용. NULL은 미확인 |
| `default_skill_id`      | `bigint`         | 기본 전투 기술. `weapon_skills.id` 참조                                                                |

| `physical_attack_types` 요소 | 게임 용어 |
| ---------------------------- | --------- |
| `standard`                   | 표준      |
| `slash`                      | 참격      |
| `strike`                     | 타격      |
| `pierce`                     | 관통      |

이 목록은 물리 공격 방식입니다. 공격력의 물리·마력·화염 등과는 다른 분류입니다.

| `upgrade_material`      | 게임 용어    |
| ----------------------- | ------------ |
| `smithing_stone`        | 단석         |
| `somber_smithing_stone` | 색 잃은 단석 |
| `none`                  | 강화 불가    |
| NULL                    | 미확인       |

저장 순서에 의미를 두지 않고 출력 시 정렬하는 방침입니다. 표시 순서와 정렬 코드는 아직 구현하지 않았습니다.
이 정렬 방침은 `physical_attack_types`에 적용합니다. 현재 DB는 빈 배열·중복 요소를 차단하지 않습니다.

### 공격력·가드 성능

**표준 변질의 최대 강화 기준**이며 캐릭터 능력치로 더해지는 공격력과 일시적 버프는 제외한 무기 자체 수치입니다. 가드 성능도 같은 무기 상태를 기준으로 합니다. 변질 불가 무기는 **기본 상태의 최대 강화 기준**입니다. 변질별·강화 단계별 수치를 저장하는 구조가 아니며, `max_upgrade_level` 컬럼은 두지 않았습니다.

| 컬럼               | 자료형    | 의미                   |
| ------------------ | --------- | ---------------------- |
| `attack_physical`  | `integer` | 물리 공격력            |
| `attack_magic`     | `integer` | 마력 공격력            |
| `attack_fire`      | `integer` | 화염 공격력            |
| `attack_lightning` | `integer` | 벼락 공격력            |
| `attack_holy`      | `integer` | 신성 공격력            |
| `critical`         | `integer` | 치명                   |
| `guard_physical`   | `numeric` | 물리 가드 시 감소율(%) |
| `guard_magic`      | `numeric` | 마력 가드 시 감소율(%) |
| `guard_fire`       | `numeric` | 화염 가드 시 감소율(%) |
| `guard_lightning`  | `numeric` | 벼락 가드 시 감소율(%) |
| `guard_holy`       | `numeric` | 신성 가드 시 감소율(%) |
| `guard_boost`      | `integer` | 가드 강도              |

정수는 0 이상, 가드 감소율은 0~100 범위만 허용합니다.

부가 효과는 **미강화·기본 상태**이며 캐릭터 능력치 보정과 일시적 버프를 제외합니다. 최대 강화 공격력과 기준이 다릅니다. 모든 컬럼은 `integer`, 0 이상입니다.

| ----------------------- | ------------------- |

| `sleep`                 | 수면 축적 수치      |
| `madness`               | 발광 축적 수치      |
| `required_strength`     | 필요 근력           |

`default_skill_id` 인덱스가 있습니다.

## `weapon_scalings`: 변질별 능력 보정

**최대 강화 기준**으로 지원하는 변질의 행만 등록합니다. 변질 불가 무기는 기본 상태를 `standard` 한 행으로 저장하고, 화면에서 표준 변질 가능으로 해석하지 않습니다. 변질 가능 여부는 `weapon_details.can_change_affinity`로 확인합니다. 이 행 구성 규칙은 입력 규칙이며, 현재 DB가 변질 가능 여부와 보정 행의 조합을 강제하지는 않습니다.

| 컬럼           | 자료형   | NULL 허용 | 의미                               |
| -------------- | -------- | --------- | ---------------------------------- |
| `game_item_id` | `bigint` | 아니요    | `weapon_details.game_item_id` 참조 |
| `affinity`     | `text`   | 아니요    | 변질 종류                          |
| `strength`     | `text`   | 예        | 근력 보정                          |
| `dexterity`    | `text`   | 예        | 기량 보정                          |
| `intelligence` | `text`   | 예        | 지력 보정                          |
| `faith`        | `text`   | 예        | 신앙 보정                          |
| `arcane`       | `text`   | 예        | 신비 보정                          |

- `(game_item_id, affinity)`가 복합 기본키입니다. 동일 무기·변질 중복을 막습니다.
- 보정 값은 `S`, `A`, `B`, `C`, `D`, `E`, `-`만 허용합니다. `-`는 보정 없음, NULL은 미확인입니다.
- 등급을 비교·정렬할 때는 `S > A > B > C > D > E` 순서입니다. 문자열 사전순으로 정렬하지 않습니다. `-`와 NULL은 등급이 아닙니다.
- 모든 무기에 13행을 요구하지 않습니다. 행이 없는 이유(미입력·지원 안 함)는 현재 스키마만으로 구분하지 않습니다.

| 값          | 변질   |
| ----------- | ------ |
| `standard`  | 표준   |
| `heavy`     | 중후   |
| `keen`      | 예리   |
| `quality`   | 상질   |
| `fire`      | 화염   |
| `flame_art` | 화염술 |
| `lightning` | 벼락   |
| `sacred`    | 신성   |
| `magic`     | 마력   |
| `cold`      | 냉기   |
| `poison`    | 독     |
| `blood`     | 피     |
| `occult`    | 신비   |

### 이름이 같아도 구분해야 하는 용어

| 저장 위치                        | 값·컬럼    | 의미                  |
| -------------------------------- | ---------- | --------------------- |
| `physical_attack_types`          | `standard` | 물리 공격 방식인 표준 |
| `weapon_scalings.affinity`       | `standard` | 표준 변질             |
| `weapon_scalings.affinity`       | `occult`   | 신비 변질             |
| `weapon_scalings.arcane`         | 보정 등급  | 신비 능력치의 보정    |
| `weapon_details.required_arcane` | 요구 수치  | 필요 신비             |
| `weapon_details.attack_magic`    | 공격력     | 마력 공격력           |
| `weapon_scalings.affinity`       | `magic`    | 마력 변질             |
| `weapon_scalings.intelligence`   | 보정 등급  | 지력 능력치의 보정    |

`required_`는 필요 능력치를 표현하기 위한 DB 접두사입니다. 화면에서는 근력·기량·지력·신앙·신비와 '필요 능력치'라는 문맥으로 표시합니다.
분류명과 아이템·기술 이름은 코드 enum이 아니라 `name`에 한국어 문자열로 저장합니다. 과거 개발 샘플에는 분류 `단검`, 아이템 `대거`, 기술 `퀵스텝`이 있었습니다. 이 ID의 숫자를 게임 용어나 고정 코드처럼 사용하지 않습니다.

## 공개 접근

모든 테이블에 RLS를 활성화했습니다. `anon`·`authenticated` 역할에는 SELECT 권한과 전체 행 조회 정책만 부여합니다.
일반 클라이언트의 INSERT·UPDATE·DELETE 권한은 제거했습니다. 현재 비공개·검수 상태 구분은 없으므로 등록된 행은 모두 공개 조회 대상입니다.
로컬 시드 입력은 일반 클라이언트가 아닌 DB 관리자 권한으로 수행합니다.

## 게임 정보와 저장 위치: 대거 예시

아래 값은 `supabase/seed.sql` 기준 예시이며, 현재 DB 전체의 스냅샷이 아닙니다. ID는 자동 생성되므로 숫자를 고정해서 설명하지 않습니다.

| 게임에서 보는 정보 | 저장 위치                                           | 시드 예시                                  |
| ------------------ | --------------------------------------------------- | ------------------------------------------ |
| 이름·종류          | `game_items.name`, `game_items.type`                | `대거`, `weapon`                           |
| 무기 유형          | `game_items.category_id` → `game_item_categories`   | 이름 `단검`, 종류 `weapon`인 분류          |
| 이미지             | `game_items.image_url`                              | 사용자가 제공한 외부 이미지 URL            |
| 콘텐츠             | `game_items.content_code`                           | `base_game`                                |
| 게임 내 설명       | `game_items.game_description`                       | 검신이 곧은 매우 짧은 단검…                |
| 공격 속성          | `weapon_details.physical_attack_types`              | `['slash', 'pierce']`                      |
| 중량·강화 재료     | `weapon_details.weight`, `upgrade_material`         | `1.5`, `smithing_stone`                    |
| 전투 기술          | `weapon_details.default_skill_id` → `weapon_skills` | 퀵스텝, FP 문자열 `3`, 기술 설명           |
| 물리 공격력·치명   | `weapon_details.attack_physical`, `critical`        | `181`, `130`                               |
| 가드 감소율        | `weapon_details.guard_*`                            | 물리 `35.0`, 나머지 네 속성 각 `20.0`      |
| 가드 강도          | `weapon_details.guard_boost`                        | `15`                                       |
| 부가 효과          | `weapon_details.scarlet_rot` 등 여섯 컬럼           | 모두 `0`                                   |
| 필요 능력치        | `weapon_details.required_*`                         | 근력 `5`, 기량 `9`, 나머지 `0`             |
| 변질별 보정        | `weapon_scalings`                                   | 13행. 표준: 근력 `D`, 기량 `B`, 나머지 `-` |

무기 하나의 상세 화면을 조회할 때 기준 행은 `game_items`입니다. 분류·무기 상세·기본 전투 기술을 연결하고, 변질별 보정은 여러 행의 목록으로 가져옵니다. 상세와 기술 연결이 선택 사항이므로 목록에서 무조건 내부 조인하면 상세 미입력 아이템이 빠질 수 있습니다.

예를 들어 다음은 공통 정보와 기본 기술을 조회하는 읽기 전용 SQL입니다. `$1`은 조회할 아이템 ID를 받는 바인딩 매개변수이며, SQL Editor에서 그대로 실행할 때는 실제 ID로 바꿉니다.

```sql
select
  i.id, i.name, i.type, i.image_url, i.content_code, i.game_description,
  c.name as category_name,
  d.weight, d.attack_physical,
  s.name as skill_name, s.description as skill_description, s.fp_cost_text
from public.game_items i
join public.game_item_categories c on c.id = i.category_id
left join public.weapon_details d on d.game_item_id = i.id
left join public.weapon_skills s on s.id = d.default_skill_id
where i.id = $1;
```

변질별 보정은 `weapon_scalings.game_item_id`로 조회합니다. 단순 조인으로 13행을 합치면 공통 아이템 정보도 13번 반복되므로, 조회 결과를 그대로 아이템 13개로 취급하지 않습니다. 변질의 화면 표시 순서도 별도로 정해야 합니다.

- 공격력·가드 성능은 자료에 명시된 최대 강화 수치, 변질 가능 무기는 표준 기준입니다. 보정은 변질별 최대 강화 등급이며, `D - B`처럼 기본→최대 표기는 마지막 등급을 사용합니다. 자료의 `상질`은 기존 코드 `quality`(표시명 상질)에 대응합니다.
- 숫자 칸의 `-`는 없음(`0`), 보정 등급의 `-`는 보정 없음으로 저장합니다. 표에 없는 수면·발광은 사용자 공통 기준에 따라 없음(`0`)으로 저장합니다.
- 변질 가능 10종은 변질표, 변질 불가 8종은 단일 보정표와 본문을 근거로 합니다. 미확인 보정·상태 이상과 확인 조건은 [데이터 확인 목록](DATA_VERIFICATION.md)에 정리하며, 확인 전에는 `NULL`을 유지합니다.
- 상아 손낫·결정 나이프는 단석 강화이지만 변질 불가입니다. 나머지 색잃은 단석 무기와 구분하며, 강화 재료만으로 변질 가능 여부를 결정하지 않습니다.
- 패리 FP는 원문에서 패링 대거 `-`, 맹고슈 `3`으로 충돌합니다. 사용자 확인에 따라 공통 전투 기술 패리의 소비 FP를 `3`으로 통일합니다. 협차의 `퀵 스텝`은 동일 원문의 기술 설명에 맞춰 `퀵스텝`으로 통일합니다.
- 게임 내 설명과 기술 설명만 분리해 저장하며 평가·운용·획득 공략은 저장하지 않습니다. 숫자 각주는 원문 연결 정보가 없어 제거합니다.
- 부가 효과는 사용자 제공 본문에서 축제의 손낫(가드 관통 성격·명중 시 룬 10), 친퀘디아(짐승 기도 위력 10%), 불의 기사 단검(화염 공격력 부여 시 상승 효과)을 요약합니다. 전투 기술 효과를 무기 자체의 상시 부가 효과로 중복 등록하지 않습니다.
- 불의 기사 단검·맹고슈는 자료의 DLC 표시에 따라 `shadow_of_the_erdtree`, 나머지 16종은 제공 목차의 본편 분류에 따라 `base_game`으로 등록합니다. 이미지 주소는 제공되지 않아 전부 `NULL`입니다.
- 자료의 적용 게임 버전과 추가 확인 항목은 [데이터 확인 목록](DATA_VERIFICATION.md)을 참고합니다.
- 기대 등록 수는 단검 18행, 무기 상세 18행, 공통 전투 기술 7행, 보정 138행입니다. 운영 DB 반영은 수행하지 않았습니다.

## 아직 구현하지 않은 범위

뼛가루 등 다른 종류의 상세 테이블, 일반 해설·댓글, 변질별 공격력, 강화 단계별 능력치는 구현하지 않았습니다. 아이템 이름 부분 검색은 현재 장비 조회 API에서 제공합니다.

## 후속 검토에서 보류한 항목

- 전회 교체 가능 여부(`can_change_ash_of_war`): 현재 도감에서 표시·필터 사용처가 확정되지 않아 추가하지 않았습니다. `can_change_affinity`나 강화 재료로 대신 추론하지 않습니다.
- 상태 이상 외 고유 효과 설명: 공통 `game_items.effect_description`에 표시용 설명으로 저장하도록 확장했습니다.
- 촉매의 마술·기도 보정: 캐릭터 능력치에 따라 달라지므로 촉매 샘플과 표시 기준을 정할 때 설계합니다. 현재 `weapon_scalings`의 등급과는 다른 정보입니다.
- 기존 세 무기는 수면·발광 축적이 모두 없다는 사용자 확인에 따라 `0`을 저장합니다. 기존 제공 수치는 그대로 유지했으며, 최신 게임 수치 및 캐릭터 보정 제외 여부를 외부 자료로 재검증한 것은 아닙니다.

## `ash_of_war_details`: 전회 상세

획득 아이템인 전회와 발동 기술인 `weapon_skills`를 구분합니다. 기본 분류는 `game_item_categories`의 전회 하나입니다.

| 컬럼                        | 자료형           | 의미                                                          |
| --------------------------- | ---------------- | ------------------------------------------------------------- |
| `game_item_id`              | `bigint`         | 기본키. `type`과 함께 `game_items(id, type)` 참조             |
| `type`                      | `game_item_type` | NULL 불가, 기본값 `ash_of_war`, 이 값만 허용                  |
| `skill_id`                  | `bigint`         | 부여하는 기술. `weapon_skills.id` 참조, NULL은 미확인         |
| `native_affinity`           | `text`           | 표시되는 기본 변질. 기존 13종 변질 코드만 허용, NULL은 미확인 |
| `applicable_armaments_text` | `text`           | 적용 가능한 무기와 제외 조건 설명, NULL은 미확인              |

- 기술 이름·설명·소비 FP는 `weapon_skills`에서 재사용합니다. 전회에 중복 컬럼을 두지 않습니다.
- 전회 이름·이미지·콘텐츠 소속·게임 내 설명 원문은 공통 `game_items`에 저장합니다.
- 기본 변질은 선택 가능한 모든 변질이나 사용자 장착 상태를 의미하지 않습니다. 적용 대상 설명으로 실제 장착 가능 여부를 자동 판정하지 않습니다.
- 기본 장착 무기는 `weapon_details.default_skill_id`가 담당합니다. 파생 기술 관계·획득 방법·공략·평가·패치 이력은 이번 범위에서 저장하지 않습니다.
- 동명의 주문과 전투 기술은 별개입니다. 휘검의 원진과 거검진 역시 별개 기술로 유지합니다.
- 외래키는 UPDATE·DELETE RESTRICT이며, `skill_id` 인덱스와 RLS·공개 SELECT 정책을 사용합니다.

## 결정 물방울: `crystal_tear`

- 영약에 배합하는 결정 물방울을 `game_items.type = 'crystal_tear'`로 등록합니다. 일반 성배병 회복량 강화용 성배의 물방울은 포함하지 않습니다.
- `category_id`는 현재 필수이므로 기본 분류 결정 물방울 하나를 등록합니다. `game_item_categories`의 역할은 후속 검토 대상입니다.
- 이름·이미지·콘텐츠 소속·게임 내 원문·효과 설명은 `game_items` 공통 필드에 저장합니다. 전용 상세 테이블과 수치·지속 시간 전용 컬럼은 두지 않습니다.
